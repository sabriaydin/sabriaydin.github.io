İçeriğe geç

Batch dilinde hata mesajları çoğu zaman bilgi vermez; betik sessizce yanlış çalışabilir. Bu yazıda hata bulma yöntemleri, sık yapılan hatalar ve düzenli betik yazmak için öneriler verilir.

Hata bulma yöntemleri

1. Komutları görünür yapmak

@echo off satırı geçici olarak yorum yapılır veya echo on ile değiştirilir. Böylece her komut, değişkenleri genişletilmiş haliyle ekrana yazılır:

rem @echo off
echo on

2. Değişken değerlerini yazdırmak

echo [DEBUG] DOSYA=[%DOSYA%] SAYAC=[%SAYAC%]

Değeri köşeli parantez içine almak, boşluk veya boş değer sorunlarını görünür kılar.

3. Adım adım durmak

pause          rem sorunlu bolgenin oncesine ve sonrasina konur

4. Komut penceresinden çalıştırmak

Betik çift tıklanarak çalıştırıldığında hata mesajı, pencere hızlıca kapandığı için okunamaz. Betik cmd penceresinden (cmd /k betik.bat veya pencerede adı yazılarak) çalıştırılırsa pencere açık kalır.

5. Çıktıyı dosyaya kaydetmek

betik.bat > cikti.txt 2>&1

Güvenli silme ve kopyalama alışkanlıkları

  • Önce listele, sonra sil. del veya rd komutundan önce aynı filtreyle dir veya echo kullanılarak etkilenecek dosyalar görülür.
  • Değişken boşsa dikkat. rd /s /q "%HEDEF%\Eski" komutunda HEDEF boşsa yol \Eski olur ve sürücü kökündeki klasör silinebilir. Silmeden önce değişkenin dolu olduğu denetlenir.
  • Tam yol kullanın. Göreli yollar betiğin nereden çalıştırıldığına göre farklı yerleri etkiler. cd /d "%~dp0" ile betiğin klasörü esas alınır.
  • Kök sürücüde işlem yapmayın. C:\ veya %USERPROFILE% gibi geniş konumlara karşı del /s ve rd /s çalıştırılmamalıdır.
  • Yedek alın. Dosyaları değiştiren betiklerin ilk testi kopyalar üzerinde yapılır.
@echo off
set "HEDEF=D:\Gecici"
if not defined HEDEF (echo HEDEF tanimli degil & exit /b 1)
if not exist "%HEDEF%\" (echo Klasor yok: %HEDEF% & exit /b 1)

echo Silinecek dosyalar:
dir /b "%HEDEF%\*.tmp"
choice /c EH /m "Silinsin mi"
if errorlevel 2 exit /b 0
del /q "%HEDEF%\*.tmp"

Betik şablonu

Aşağıdaki iskelet, rehberdeki konuların çoğunu düzenli biçimde bir araya getirir:

@echo off
setlocal enableextensions
cd /d "%~dp0"
title Betik Adi

rem ============================================
rem  Amac   : Betigin ne yaptigi
rem  Yazar  : Ad
rem  Tarih  : 2026-10-13
rem  Gerek  : Yonetici yetkisi gerekmez
rem ============================================

rem ---- Ayarlar ----
set "KAYNAK=%~dp0girdi"
set "LOG=%~dp0betik_log.txt"

rem ---- Ana akis ----
call :gunlukle "Basladi"
call :isle "%KAYNAK%"
if errorlevel 1 (
    call :gunlukle "HATA: islem basarisiz"
    exit /b 1
)
call :gunlukle "Bitti"
exit /b 0

rem ---- Alt programlar ----
:gunlukle
echo [%date% %time%] %~1 >> "%LOG%"
echo %~1
exit /b 0

:isle
if not exist "%~1\" (
    echo Klasor bulunamadi: %~1
    exit /b 1
)
rem ... asil islem ...
exit /b 0

Okunabilirlik önerileri

  • Ayarlar (yollar, adlar) betiğin başında tek yerde toplanır.
  • Her alt programın üstüne ne yaptığını anlatan rem satırı yazılır.
  • Değişken adları anlamlı ve büyük harfle yazılır: YEDEK_KLASORU, SAYAC.
  • Parametre kullanan alt programlar %~1 ile başlar ve ilk satırda adlandırılır: set "AD=%~1".
  • Tüm set komutlarında set "X=deger" biçimi kullanılır.
  • Tekrarlanan kod alt programa taşınır (call :ad).
  • Betik her zaman bir çıkış koduyla biter (exit /b 0 veya exit /b 1).

Güvenlik önerileri

  • Kullanıcıdan alınan girdi (set /p) doğrudan komut içinde kullanılmamalıdır. &, |, > gibi karakterler beklenmedik komut çalıştırabilir. Girdi doğrulanmalı, yalnızca beklenen karakterlere izin verilmelidir.
  • İnternetten indirilen betikler çalıştırılmadan önce Not Defteri'nde okunmalıdır. Anlaşılmayan satırı olan betik çalıştırılmaz.
  • Betiklerde parola düz metin olarak saklanmamalıdır.
  • Yönetici yetkisi gerekmeyen betikler yönetici olarak çalıştırılmamalıdır (bkz. Dağıtım ve Yönetici Yetkisi).

Özet

  • Hata bulmak için echo on, değişken yazdırma ve cmd /k ile çalıştırma kullanılır.
  • Sık hatalar tırnak, boşluklu set, gecikmeli genişletme ve boş değişkenlerden kaynaklanır.
  • Silme işlemleri öncesinde listeleme ve değişken denetimi yapılır.
  • Düzenli şablon ve kısa alt programlar betiği okunur ve bakımı kolay kılar.
