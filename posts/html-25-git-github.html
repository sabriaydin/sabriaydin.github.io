Git, dosyalardaki değişiklikleri kaydeden ve geçmişe dönmeyi sağlayan sürüm kontrol sistemidir. GitHub ise Git depolarını internette barındıran ve GitHub Pages ile ücretsiz web sitesi yayınlamayı sağlayan hizmettir. Bir sayfa üzerinde çalışırken "çalışan son sürüm" kaybolmaz, bozulan bir değişiklik geri alınabilir ve çalışma birden fazla kişiyle paylaşılabilir.

Temel kavramlar

KavramAnlamı
Repository (depo)Projenin dosyalarını ve tüm değişiklik geçmişini içeren klasör.
CommitDeğişikliklerin açıklama notuyla kaydedilmiş bir anlık görüntüsü.
Branch (dal)Ana çalışmayı bozmadan paralel olarak geliştirme yapılan çizgi. Ana dal genellikle main adını taşır.
Remote (uzak depo)GitHub üzerindeki depo kopyası. Varsayılan adı origin'dir.
Working directory / Staging areaÇalışma klasörü ve bir sonraki commit'e eklenmek üzere seçilmiş değişikliklerin bekleme alanı.

Kurulum ve ilk ayar

Git, git-scm.com adresinden (Windows için "Git for Windows") indirilir. Kurulum ve ayrıntılar için Git yazısına bakılabilir. Kurulumdan sonra bir kez ad ve e-posta tanımlanır; commit'lerde bu bilgiler görünür:

git config --global user.name "Ad Soyad"
git config --global user.email "eposta@ornek.com"
git config --global init.defaultBranch main

git --version
GitHub'da e-posta adresini gizlemek isteniyorsa GitHub'ın verdiği ...@users.noreply.github.com adresi kullanılabilir.

Yeni depo oluşturma ve ilk commit

mkdir sayfam
cd sayfam
git init                      # klasörü Git deposu yapar

# index.html ve style.css dosyaları oluşturulur

git status                    # değişiklikleri gösterir
git add index.html style.css  # dosyaları commit'e hazırlar (hepsi için: git add .)
git commit -m "İlk sürüm: ana sayfa ve stil"

git add seçilen değişiklikleri sahneye alır, git commit bunları açıklamasıyla birlikte kalıcı olarak kaydeder. Bu iki adımlı yapı, bir işte yapılan farklı değişikliklerin ayrı commit'ler olarak kaydedilmesini sağlar.

İyi commit mesajı

  • Kısa ve açıklayıcı olmalıdır: "Menüye iletişim bağlantısı eklendi", "Mobil görünümde taşma düzeltildi".
  • "düzeltme", "son", "deneme" gibi anlamsız mesajlardan kaçınılır.
  • Küçük ve sık commit atmak, büyük ve nadir commit atmaktan daha iyidir; geri almak da kolaylaşır.

KomutNe yapar?

GitHub'a yükleme

  1. github.com üzerinde hesap açılır ve New repository ile boş bir depo oluşturulur (README, .gitignore ekleme seçenekleri işaretlenmez).
  2. Açılan sayfadaki adres kopyalanır: https://github.com/kullanici/sayfam.git
  3. Yerel klasörde aşağıdaki komutlar çalıştırılır:
git remote add origin https://github.com/kullanici/sayfam.git
git branch -M main
git push -u origin main

İlk push sırasında GitHub kimlik doğrulaması ister. Windows'ta Git ile birlikte gelen Git Credential Manager bir tarayıcı penceresi açar ve GitHub hesabıyla oturum açmak yeterlidir. Hesap parolası ile push yapılamaz; komut satırı kimlik doğrulaması için tarayıcı girişi veya kişisel erişim anahtarı (Personal Access Token) kullanılır.

-u parametresi, bu dalın uzak depoyla ilişkilendirilmesini sağlar; sonraki yüklemelerde yalnızca git push yazmak yeterli olur.

Günlük çalışma düzeni

git pull                          # önce güncel hali al
# ... dosyalarda değişiklik yap ...
git add .
git commit -m "Hakkında sayfası eklendi"
git push

GitHub Pages ile yayınlama

Depoda Settings > Pages bölümünde Source olarak "Deploy from a branch", dal olarak main ve klasör olarak / (root) seçilir. Birkaç dakika sonra site https://kullanici.github.io/sayfam/ adresinde yayına girer. Bundan sonra her git push, siteyi otomatik günceller (bkz. HTML Rehberi: Proje ve Yayınlama).

Dallar (branch) ile güvenli deneme

Yeni bir özellik denenirken ana dalın bozulmaması için ayrı dal açılır:

git switch -c koyu-tema        # yeni dal aç ve geç
# ... değişiklikleri yap, commit at ...
git switch main                # ana dala dön
git merge koyu-tema            # deneme başarılıysa birleştir
git branch -d koyu-tema        # işi biten dalı sil

Deneme beğenilmezse dal hiç birleştirilmeden silinir (git branch -D koyu-tema) ve ana dal etkilenmez.

.gitignore: takip edilmeyecek dosyalar

Depoya girmemesi gereken dosyalar (gizli anahtarlar, derleme çıktıları, işletim sistemi dosyaları) kök dizindeki .gitignore dosyasına yazılır:

.DS_Store
Thumbs.db
node_modules/
.env
*.log
Parola, API anahtarı gibi gizli bilgiler depoya commit edilmemelidir. Yanlışlıkla commit edilirse GitHub'a gönderilmemiş olsa bile önce anahtarın değiştirilmesi gerekir; geçmişten silmek tek başına yeterli güvenlik sağlamaz.

Geri alma işlemleri

DurumKomut
Commit edilmemiş dosya değişikliğini atmakgit restore dosya.html
git add ile eklenen dosyayı sahneden çıkarmakgit restore --staged dosya.html
Son commit mesajını düzeltmek (henüz push edilmediyse)git commit --amend -m "yeni mesaj"
Yayınlanmış bir commit'in etkisini geri almakgit revert COMMIT_KODU (geri alan yeni bir commit oluşturur)
Eski bir sürüme bakmakgit switch --detach COMMIT_KODU, ardından git switch main ile dönülür
git restore ile atılan commit edilmemiş değişiklikler geri getirilemez. git reset --hard ve git push --force komutları da veri kaybettirebilir; ne yaptığı bilinmeden kullanılmamalıdır. Paylaşılan geçmişi değiştirmek yerine git revert tercih edilir.

Sık karşılaşılan hatalar

HataÇözüm
rejected ... fetch first / non-fast-forwardUzak depoda yerelde olmayan commit'ler var. Önce git pull, sonra git push çalıştırılır.
fatal: not a git repositoryKomut, git init yapılmamış bir klasörde çalıştırılıyor; doğru klasöre geçilmelidir.
Author identity unknownuser.name ve user.email ayarlanmamış; ilk ayar komutları çalıştırılır.
Birleştirme çakışması (merge conflict)İki dalda aynı satır değişmiş. Dosyadaki <<<<<<<, =======, >>>>>>> işaretleri arasından doğru sürüm bırakılıp işaretler silinir, ardından git add ve git commit yapılır.

Komut satırı istemeyenler için

GitHub Desktop uygulaması, aynı işlemleri (commit, push, pull, dal) görsel arayüzle yapar. Visual Studio Code'da da sol taraftaki Source Control paneli yerleşik olarak Git desteği sunar.

Özet

  • git init > git add > git commit ile değişiklikler kaydedilir.
  • git push ve git pull ile GitHub ile eşitlenir; GitHub Pages ile site yayınlanır.
  • Deneme için dal açılır, olumlu sonuç alınırsa main'e birleştirilir.
  • Gizli bilgiler asla commit edilmez; .gitignore kullanılır.
  • Paylaşılan geçmişi değiştiren komutlar yerine git revert kullanılır.
